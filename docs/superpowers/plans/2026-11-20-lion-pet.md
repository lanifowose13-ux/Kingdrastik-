# Lion Pet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Drastik, a proud, sassy Tamagotchi-style lion, as a shared rules core plus two homes: a Claude artifact page (Home A) and a Claude Code companion (Home B).

**Architecture:** `lion-pet/core/` holds pure, UI-free logic (state, decay, actions, moods, growth, lines). Home A inlines the core into one HTML page at build time. Home B is a Node CLI called by Claude Code hooks (to record events) and by the status line (to draw him). The two homes keep **two separate lions** that share character and rules; there is no sync.

**Tech Stack:** Node 20+ ES modules, `node:test` (no dependencies), inline SVG/CSS for Home A, Claude Code `statusLine` and hooks for Home B, Playwright (pre-installed) for the page check.

**Spec:** `docs/superpowers/specs/2026-11-20-lion-pet-design.md`

## Global Constraints

- Needs are `hunger`, `energy`, `fun`, `pride`, each 0 to 100, **never below 10** (floor). Bond is 0 to 200.
- The lion never dies and never leaves. No guilt-trip copy, no streak pressure, no notifications.
- Sass is affectionate and never insults the user's real work, body or worth.
- Stages in order: `cub`, `teen`, `adult`, `king`. Stage only ever advances.
- Moods: `regal`, `smug`, `playful`, `hangry`, `sleepy`, `sulking`, `furious`.
- Actions: `feed`, `play`, `nap`, `groom`, `praise`, `roar`, each with a cooldown.
- Working name `Drastik`; the name is a parameter, never hard-coded in logic.
- Home A: self-contained HTML, mobile-first (works at 390px wide, 16px side gutter, no horizontal scroll), light and dark theme, storage calls wrapped in try/catch.
- All new code lives under `lion-pet/`. Do not touch Paper Trader files.
- Numbers below are the plan's starting values (the spec left them to the builder); keep them in one `CONFIG` object in `core/lion.mjs`.

## Review Focus

- System clock moves backwards (`now < lastTick`): state must not change, nothing goes negative. (Task 1)
- User away for 100 days: needs stay at the floor of 10, bond never negative, greeting still in character. (Task 2)
- Home B state file is missing, empty or corrupt JSON: a fresh lion is created, the CLI never crashes the hook. (Task 6)
- Hook stdin is empty or not JSON: the CLI exits 0 silently so Claude Code is never blocked. (Task 6)
- Home A storage unavailable or Ask-Claude fails or is slow: page still works with a new in-memory lion and canned lines. (Tasks 4 and 5)

## File Structure

```
lion-pet/
  package.json                 type=module; "test": "node --test"
  core/lion.mjs                state, tick, act, mood, stage, greeting (pure)
  core/lines.mjs               canned lines + pickLine
  core/lion.test.mjs
  core/lines.test.mjs
  home-a/page.src.html         page template with a /*CORE*/ marker
  home-a/build.mjs             inlines core into dist/lion-pet.html
  home-a/build.test.mjs
  home-b/cli.mjs               `event <name>` and `status` subcommands
  home-b/sprites.mjs           small text art per stage and mood
  home-b/cli.test.mjs
  home-b/README.md             how to wire the status line and hooks
```

### Task 1: Core state, decay and actions

**Files:**
- Create: `lion-pet/package.json`, `lion-pet/core/lion.mjs`
- Test: `lion-pet/core/lion.test.mjs`

**Interfaces:**
- Produces:
  - `CONFIG` (frozen): decay per hour `{hunger: 6, energy: 4, fun: 5, pride: 3}`, `floor: 10`, `cooldownsMs: {feed: 600000, play: 300000, nap: 1200000, groom: 600000, praise: 300000, roar: 180000}`, `awayCapHours: 12`.
  - `createLion(now: number, name = 'Drastik'): LionState` with `{name, stage: 'cub', needs: {hunger: 80, energy: 80, fun: 80, pride: 80}, bond: 0, bornAt: now, lastTick: now, cooldowns: {}, lastAction: null}`.
  - `tick(state, now, opts?: {restWhileAway?: boolean}): LionState`, returns a new object.
  - `act(state, action, now): {state: LionState, ok: boolean, reason?: 'cooldown' | 'unknown'}`.
  - `mood(state, now): Mood`.

- [ ] **Step 1: Write failing tests** in `lion.test.mjs`: `createLion` has the stated defaults; `tick` after 2h drops hunger by 12 (80 to 68); `tick` with `now < lastTick` returns an equal state (Review Focus); `tick` after 1000h leaves every need at exactly 10 (floor) and never below; `tick` with `restWhileAway: true` after 3h raises energy and still drops hunger.
- [ ] **Step 2: Write failing action tests:** `act(feed)` at hunger 40 gives hunger 70 (+30), sets `cooldowns.feed = now + 600000`; a second `feed` inside the cooldown returns `ok: false, reason: 'cooldown'` and an unchanged state; `play` gives fun +25, energy −15; `nap` gives energy +40, hunger −5; `groom` gives pride +25; `praise` gives pride +30; `roar` gives pride +10, fun +10, energy −10; all needs clamp to 100; unknown action returns `reason: 'unknown'`.
- [ ] **Step 3: Write failing mood tests** (priority order): three or more needs below 30 gives `furious`; pride below 30 gives `sulking`; hunger below 30 gives `hangry`; energy below 30 gives `sleepy`; a `feed` or `praise` within the last 10 minutes gives `smug`; fun above 70 and energy above 60 gives `playful`; otherwise `regal`.
- [ ] **Step 4: Run** `cd lion-pet && node --test` and confirm the failures.
- [ ] **Step 5: Implement** `CONFIG`, `createLion`, `tick`, `act`, `mood` in `core/lion.mjs`. `tick` decays by `elapsedHours` capped at `awayCapHours`, applies the floor, and sets `lastTick = now` (no change if time went backwards). Bond: add 2 to bond on any successful action whose target need was below 70 before the action, else 0.
- [ ] **Step 6: Run tests, confirm all pass.**
- [ ] **Step 7: Commit** `git add lion-pet && git commit -m "feat(lion-pet): core state, decay, actions, moods"`.

### Task 2: Growth and the return greeting

**Files:**
- Modify: `lion-pet/core/lion.mjs`
- Test: `lion-pet/core/lion.test.mjs`

**Interfaces:**
- Consumes: Task 1's `LionState`, `tick`.
- Produces:
  - `STAGES` = `[{name:'cub'},{name:'teen', minDays: 2, minBond: 20},{name:'adult', minDays: 7, minBond: 60},{name:'king', minDays: 21, minBond: 120}]` exported in `CONFIG.stages`.
  - `advanceStage(state, now): LionState`: moves up at most one stage per call; never down.
  - `awayGreeting(awayMs: number): 'short' | 'medium' | 'long'` (under 2h, under 24h, 24h or more) for line selection.

- [ ] **Step 2: Run, confirm failures.**
